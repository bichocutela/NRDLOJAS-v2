# Academia NRD (V3 → V2)

The native Compose port preserves the three V3 modes (Aprender, Prova, Caixa Livre), six missions, 23 original steps, keypad groups, operator/customer displays, hints, errors, stars and session history. Flutter source reference: NRDLOJAS-V3/lib/src/training/{training_hub_page,cashier_simulator_page}.dart. Educational sequences do not execute real PDV operations.

Mestre → Aba Treinamento selects OFF / TEST / ALL exclusively. Initial content comes from assets/training-default.json and starts OFF. Save TEST to prepare content privately. The protected editor is always accessible to Mestre even while the drawer entry is disabled. Preview never publishes. TEST/OFF payloads require the authenticated Mestre at the Firestore rules layer; hiding the drawer is not the access boundary.

Firestore config/training_access exposes only visibility/revision, letting connected public clients notice a future ALL activation without polling. config/training contains visibility/revision/payload JSON. Both save atomically with a revision conflict guard. Logout clears the previous snapshot. No new Supabase tables, cron jobs or background catalog scans are introduced.

All keys (including blank positions), commands, input values, both display texts/images and each mission's title, availability, steps, expected key and instructions can be edited remotely. Built-in commands are MESSAGE, APPEND, CLEAR, BACK and RESET; arbitrary executable code is deliberately not a command. Text placeholders: {entrada}, {tecla}, {missao}. Guided steps use step displays unless the key's guided override is enabled. Image URLs must use HTTPS; public Google Drive sharing links are accepted in both displays, with file/open/uc/thumbnail conversion and resource-key preservation. Source links remain editable and load directly from Google without copying to Supabase; gallery imports are sampled and compressed to WebP, maximum 1200 px and 700 KB, before the existing media uploader. Layout stays native; changing content needs no APK update.

The training bell is opt-in, respects Android permission and general NRD notification settings, and subscribes only to training_updates. Publishing new/enabled missions in ALL sends an authoritative data-only NEW_TRAINING notification via the existing send-fcm endpoint; Test never broadcasts. Mestre can retry using Avisar novo treinamento. Server reads saved content and deduplicates IDs in server-only training_announcements documents; client deduplicates too, verifies current public visibility/mission availability and opens training on notification tap. Re-editing an already announced mission does not resend it. A newly created mission has a new UUID.

Verification: Node tests cover publishing authorization, private content, authoritative payloads, duplicate sends, leases and retry; Robolectric covers all six original mission flows, visibility, wrong-key behavior, editable commands, serialization and screen navigation. Existing price/promotion/encarte regression tests remain enabled.
